# AI 经营助手安全规则与故障处理

## Agent 能力边界

AI 经营助手可以调用只读工具查询 SKU、条码、实时库存、成本和库存金额，可以检索 ERP 操作手册，也可以为单个 SKU 生成销售待确认预览。

DeepSeek 负责理解自然语言和选择工具。真实业务结果来自 ERP 后端，模型不能直接连接或修改 MySQL。目前 Agent 没有直接确认销售、直接创建销售单、入库、退货、库存校正或删除数据的工具。

## 写操作确认原则

销售口令只会生成预览。真正写入必须由登录用户点击确认按钮，后端再调用原有销售业务服务执行。聊天中只输入“确认”不能代替确认接口。涉及库存的其他写操作，在以后开放时也应继续采用“预览—人工确认—业务服务执行”的机制。

## RAG 知识库原则

操作方法、字段含义、业务规则和常见故障由 `search_erp_manual` 检索操作手册后回答。RAG 检索不会查询实时库存，也不会修改数据库。回答应显示实际使用的文档和章节来源；手册没有依据时，Agent 应明确说明未找到，不能编造功能。

## 常见错误处理

- `SKU_NOT_FOUND`：没有找到商品，核对货号、尺码、条码或内部 SKU。
- `SKU_AMBIGUOUS`：条件匹配多个 SKU，补充货号、尺码或条码。
- `INSUFFICIENT_STOCK`：可用库存不足，降低数量、先正常入库或核对库存。
- `AGENT_ACTION_EXPIRED`：销售预览已超过有效期，重新描述销售指令。
- `AGENT_PREVIEW_STALE`：预览后库存或成本发生变化，重新生成并核对。
- `AGENT_ACTION_CANCELLED`：预览已取消，需要重新生成新预览。
- `AGENT_ACTION_NOT_FOUND`：操作不存在或不属于当前账号，核对账号和操作编号。
- HTTP 401：登录令牌失效，重新登录。
- HTTP 503 或“AI 服务暂时不可用”：检查 DeepSeek API Key、网络和模型服务状态后重试。

## 数据与密钥安全

数据库密码、JWT 密钥和 DeepSeek API Key 只能保存在后端 `.env`，不能写入手机端代码、截图公开或提交到 Git 仓库。手机端只保存登录后获得的短期访问令牌和必要的当前用户信息。
